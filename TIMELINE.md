# Project Timeline — 7-Step Workflow Delivered by October

Workflow (no payment step — confirmed out of scope):
1. Intake → 2. Extraction → 3. Confirmation → 4. Policy Validation
→ 5. Risk Assessment → 6. Claim Decision → 7. Closure + Feedback

---

## AUGUST (Review 1) — Pipeline skeleton, text-only, no voice/OCR/RAG yet

**Build:**
- Step 1 (Intake): text input only (voice UI not built yet — this is planned for Sept)
- Step 2 (Extraction): LLM extracts fields from text; missing-field loop works (`mandatory_field_checker`)
- Step 2 (Documents): file upload endpoint works; document_type validated against claim_type; wrong type → re-upload prompt. No OCR — just accept/store/tag.
- Step 3 (Confirmation): API returns extracted fields for display — **no TTS yet**, text-only confirmation
- Step 4 (Policy Validation): active/expired check against PostgreSQL — real, working
- Step 5 (Risk Assessment): rule-based fraud detector — real, working
- Step 6 (Claim Decision): approved / denied / flagged_for_review / manual_review — real, working
- Step 7 (Closure): `closure_status` distinguishes closed vs pending_review — real, working. **No feedback capture yet.**

**What's honestly NOT done by end of August:**
- No voice (speak claim / hear response)
- No OCR on documents (text extraction from photos/PDFs)
- No RAG-based coverage checking (still amount-only stub)
- No feedback survey

**Review 1 claim:** *"Full text-based pipeline covering intake through closure, with working multi-turn field prompting, document upload with type validation, rule-based fraud detection, and decision routing. Voice, OCR, and RAG coverage checking are architected and scheduled for September."*

---

## SEPTEMBER (Review 2) — Voice + document intelligence + real coverage reasoning

**Build:**
- Step 1 (Intake): faster-whisper STT wired in — claimant can actually speak
- Step 2 (Extraction): OCR (pytesseract/pdfplumber) extracts text from uploaded documents; extracted amounts/dates from documents feed into extraction, not just claim text
- Step 2 (Documents): auto-classification — system checks if uploaded content actually matches the claimed document_type (not just filename/type tag), improves the "wrong document" rejection from a label-check to a content-check
- Step 3 (Confirmation): Piper TTS wired in — system actually speaks the extracted fields back, not just displays them
- Step 4 (Policy Validation): coverage_checker replaced with real RAG — pgvector similarity search over `policy_embeddings` + LLM reasoning over retrieved clauses; deductible math already exists from August
- Step 5 (Risk Assessment): fraud detector enhanced to use document-derived data (e.g. repair estimate amount vs claimed amount mismatch)
- Step 6 (Claim Decision): unchanged logic, now backed by real coverage reasoning instead of amount-only stub
- Step 7 (Closure): decision + reasoning now spoken via TTS, not just returned as text

**What's honestly NOT done by end of September:**
- No feedback capture yet
- No adjuster-facing UI (adjusters exist in DB, get assigned, but there's no dashboard to view/act on assigned claims)

**Review 2 claim:** *"Voice-to-voice claim intake fully functional. Documents are OCR'd and auto-classified. Coverage decisions are RAG-grounded against actual policy clauses, not simple amount checks. All 7 workflow steps are now voice-and-text dual-channel except feedback capture, which lands in October alongside DevOps."*

---

## OCTOBER (Review 3) — Feedback loop closes, DevOps, deployment

**Build:**
- Step 7 (Closure + Feedback): feedback capture endpoint + simple survey (satisfaction rating + comment), tied to `closure_status = closed` or post-manual-review closure
- Adjuster dashboard (minimal): list of assigned claims, view extracted data + documents, mark flagged claims as resolved (manual override → triggers closure)
- Docker Compose: all services containerized end-to-end
- CI/CD: GitHub Actions runs pytest on every push
- Deployment: Vercel (frontend) + Railway (backend + Postgres)
- Full API docs (OpenAPI/Swagger, already auto-generated by FastAPI — just polish)
- README + setup guide finalized

**By end of October, the full 7-step workflow is complete and demonstrable end-to-end:**
```
Speak claim → missing info prompted by voice → attach documents →
wrong document rejected, correct one accepted → extracted fields
spoken + shown back → policy validated against real coverage
reasoning → fraud/risk checked → decision made (approved/denied/
flagged) → routed to adjuster if needed → closed with spoken +
written reasoning → feedback captured
```

**Review 3 / Viva claim:** *"All 7 stages of the claim workflow are implemented end-to-end, voice-first with text fallback throughout. Payment disbursement is explicitly out of scope — approved claims are routed to the adjuster/finance team, who handle payout outside this system, which is a standard and defensible boundary for an academic MVP given PCI-DSS and payment-gateway compliance requirements."*
